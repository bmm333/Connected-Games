# ADR003: Java 25 and Spring Boot 4 for the Backend Services

- **Status:** Accepted
- **Date:** 2026-10-26
- **Scope:** Language and framework of the backend services

## Context

The backend services are mostly I/O-bound: REST APIs, database access and message
handling. The course recommends Java and allows different languages per microservice.

## Decision

Every backend service uses **Java 25** (current LTS) with **Spring Boot 4.1** and is
built with **Gradle (Kotlin DSL)**. The Java toolchain is downloaded automatically by
Gradle when it is missing (ADR008).

## Consequences

### Positive

- Spring Boot provides security, data access, migrations, metrics and testing support
  out of the box.
- One backend language: either team member can review any service.

### Costs and trade-offs

- Each service runs its own JVM, which uses more memory than a native binary.

## Alternatives considered

- **C++ for the services:** rejected. No performance gain for I/O-bound work and much
  slower development.
- **A second backend language (for example C#) for some services:** rejected. Two
  stacks cost way too much of our time in our team.
- **Maven:** rejected in favour of Gradle, which we already know from Android
  development and which supports a version catalog.
