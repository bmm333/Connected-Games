# ADR005: Contract-First Integration with OpenAPI, AsyncAPI and JSON Schema

- **Status:** Accepted
- **Date:** 2026-10-26
- **Scope:** Interfaces between web, services and edge

## Context

Programs written in different languages exchange messages: the web application
(TypeScript), the services (Java) and the edge (C++). The course asks for REST APIs
documented with Swagger/OpenAPI in YAML and for a definition of the MQTT topics.

## Decision

`contracts/` is the single source of truth and is written before the implementation:

1. **OpenAPI 3.1, one file per service:** `catalog.yaml` and `match.yaml` (read
   operations for the first milestone), exposed under `/api/<service>`. Errors use
   RFC 9457 `application/problem+json`.
2. **AsyncAPI 3.1** for MQTT (`events.yaml`), written from the point of view of the
   edge: it sends `MatchStarted`, `GoalScored` and `MatchEnded` on `matchEvents` and
   receives `EventsAcknowledged` on `hubAck`.
3. **JSON Schema (draft-07)** for every event payload, built on a shared envelope
   (`eventId`, `tenantId`, `venueId`, `gameId`, `matchId`, `seq`, `type`,
   `occurredAt`, `source`, `payload`).
4. **Naming:** field names and enum values in English, identical in every contract:
   `INDIVIDUAL`/`TEAM`, `RED`/`BLUE`, `FREE`/`OCCUPIED`/`OFFLINE`/`MAINTENANCE`.
5. **Sides are not teams:** `side` is the physical side of the table. Team names are
   chosen by users and attached to a side in `MatchStarted`.
6. TypeScript types are generated with `openapi-typescript` (`npm run gen:api` in
   `web/`) and committed.
7. Contracts are validated with Redocly and the AsyncAPI CLI, and contract changes have
   their own pull request.

## Consequences

### Positive

- Web and services are built in parallel against the same definitions.
- Interface errors appear in review, not during integration.
- The documentation required by the course comes from the contracts themselves.

### Costs and trade-offs

- Generated types must be regenerated when a contract changes.

## Alternatives considered

- **Code-first (contract generated from the Spring controllers):** rejected. The
  contract would follow the implementation, and the web would wait for the backend.
- **gRPC and Protobuf:** rejected. Poor fit for browsers and MQTT, and the course asks
  for OpenAPI.
- **GraphQL:** rejected. Unnecessary for these read patterns.
