# ADR008: Local Environment with Docker Compose and a Gradle Version Catalog

- **Status:** Accepted
- **Date:** 2026-10-26
- **Scope:** Development environment and backend build

## Context

We both need the same infrastructure with one command, and six services
built with Gradle must use the same versions of plugins and libraries.

## Decision

### Docker Compose

1. A `docker-compose.yml` at the repository root starts **PostgreSQL and Mosquitto**.
   Services are run from the IDE or with Gradle during development.
2. Image versions are pinned (`postgres:18.6`, `eclipse-mosquitto:2.0.22`).
3. PostgreSQL has a healthcheck (`pg_isready`) and an initialization script that
   creates one user and one schema per service (ADR006).
4. Secrets live in `.env`, which is not committed; `.env.example` documents every
   variable. The PostgreSQL host port is configurable (`POSTGRES_HOST_PORT`) for
   machines that already run PostgreSQL.

### Gradle

1. One multi-project build under `services/`, with a single wrapper and
   `settings.gradle.kts`.
2. A **version catalog** (`services/gradle/libs.versions.toml`) holds the versions of
   the plugins and of the libraries not managed by Spring Boot (springdoc, ArchUnit).
3. A Java 25 toolchain, downloaded automatically through the foojay resolver plugin.
4. The `architecture-rules` module is part of the build and is used as a test
   dependency by the services (ADR004).

## Consequences

### Positive

- `cp .env.example .env && docker compose up -d` gives a working environment.
- Upgrading a library is a one-line change for every service.

### Costs and trade-offs

- Bind mounts of missing files make Docker create empty root-owned directories, so
  Compose must be started from a branch that contains `infra/docker/`.
- Initialization scripts run only on an empty volume: changing them requires
  `docker compose down -v`.

## Alternatives considered

- **Running every service in Compose during development:** rejected. Slow rebuilds and
  harder debugging.
- **One Gradle wrapper per service:** rejected. Versions drift between services.
- **Versions in `gradle.properties`:** rejected. No type-safe accessors and no IDE
  completion.
